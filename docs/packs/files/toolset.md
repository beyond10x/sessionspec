The file tools an agent calls, as conceptual tools a harness binds its own tools to: read_file, write_file, edit_file, list_dir, search, move, copy and delete. Each tool is one command, typed by its input, its answer and its effect: which file it reads, creates, changes or removes. A file lives in a workspace (`agentic.workspace`). Every tool that writes names a live lease of that workspace and is refused without one; reading needs none. An edit names the content it expects, so an edit over a file that changed since it was read is refused. Which concrete tool of which harness plays a conceptual tool is a binding, not this block.
