An experiment simulates a committed architecture under a load, faults, a work mode and a profile, changes it by mutations, and searches the variants exhaustively or by fitting. Each variant is one point of the search: the values it changed, its measured KPIs, its fitness and whether it is feasible.

## KPIs

4 KPIs from the [KPI catalogue](../../kpis-catalogue.md). A gate must be zero for a variant of an architecture to count.

### Completeness

| KPI | unit | better | gate | status |
|---|---|---|---|---|
| `variants_feasible_share`<br/>Share of recorded variants that pass every gate.<br/><small>How: Variants whose gate KPIs are all 0 (or 1 for a complete share) divided by VariantRecorded events. A variant that fails a gate does not count in the ranking.</small> | share | higher | – | simulated<br/><small>source: design</small> |

### Quality

| KPI | unit | better | gate | status |
|---|---|---|---|---|
| `harness_effect_points`<br/>Change in pass rate caused by a change of harness at a fixed model.<br/><small>How: Pass rate of the variant with the changed harness minus pass rate of the baseline, in percentage points, over the same tasks and seeds.</small> | points | higher | – | planned<br/><small>source: research/2610.35971</small> |
| `ranking_reversal_share`<br/>Share of model comparisons whose ranking reverses under another harness.<br/><small>How: Pairs of models ranked in opposite order under two harnesses divided by pairs compared. A high share means a model ranking holds for one harness only.</small> | share | lower | – | planned<br/><small>source: research/2610.35348</small> |
| `prediction_error`<br/>Distance between a simulated KPI and the same KPI measured on a real run.<br/><small>How: Absolute difference between the simulated and the observed value of a KPI, divided by the observed value. A profile whose predictions miss is refitted.</small> | ratio | lower | – | planned<br/><small>source: design</small> |


## Settings

The settings a part of this block carries in an architecture document. `agenticspec sim check` refuses any other setting (`setting_unknown`) and a value outside its type (`setting_invalid`); the contract copies a setting into the ports it narrows. The last rows of each table are the settings every part takes. What no setting here types (a file, a path, an audience, the use of a model) goes into the part's `notes`, a map with free keys and values that the check takes as written and nothing reads.

A part `experiment`:

| setting | type | unit | default | contract | what |
|---|---|---|---|---|---|
| `kind` | string |  |  |  | What the experiment compares. |
| `count` | integer of at least 1 |  | `1` |  | How many copies of the part run. |
| `per` | part |  |  |  | One copy of the part for each copy of the named part. |
| `notes` | notes |  |  |  | Free notes on the part, a map with keys and values of any kind: what no setting of its block types. The check takes any map; the simulator, the search and the contract never read it. |
