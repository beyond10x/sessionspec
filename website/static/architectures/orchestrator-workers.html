Architecture · optimization result

orchestrator-workers

An orchestrator agent takes every task, spends its model calls on handing it out, and dispatches it over an order link to a worker swarm whose copies start one after another. Task-specific sub-agents helped (+5.91, +4.46) and general stage sub-agents hurt (-0.70, -2.31) (2609.32459); sub-agent concurrency helped only on the largest tasks (2610.10263); an author-reviewer loop cost $0.95-1.07 per file against $1.98-2.91 for a multi-agent workflow (2610.09995). The simulator charges the orchestrator the profile role `orchestrator` for every task, counts those calls as coordination calls, and makes it a queue every task passes; the workers take the handed tasks in order. With an orchestrator handing out the work no two copies race for one task, so a start stagger here only holds copies back. The simulator does not model how the orchestrator splits a task, results that come back to it, nor any gain or loss in success from orchestration: workers keep the coding role's pass rates.
